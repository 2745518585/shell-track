# 架构与数据生命周期

Shell Track 的任务单位是一个交互式 shell 会话，或一个由 shell 执行的单次命令。当前没有 shell 内逐条命令跟踪，也不会从输出猜测命令何时开始或结束。

## 进程与模块

```text
原终端 ⇄ CLI ── 输入 / 尺寸 WebSocket ──┐
          └── 输出 HTTP 分页 ───────────┤
                                      │
WinUI 窗口 ── 查询 / 管理 HTTP ────────┼── Host ⇄ ConPTY ⇄ shell / 子进程
                                      │     ├── 元数据 / 输出 / 尺寸记录
自动化程序 ── HTTP / 状态 WebSocket ───┘     └── 短时桌面通知辅助进程
```

Host 是当前用户的后台进程，按数据根目录单实例运行，不是 Windows 服务。CLI 和桌面客户端可以自动启动它；后台启动使用隐藏窗口。不同的数据根目录允许独立运行不同实例。

| 项目 | 项目引用 | 职责 |
|---|---|---|
| Core | 无 | 终端接口、增量 UTF-8 与纯文本日志 |
| Contracts | 无 | API DTO、枚举、事件和序列化约定 |
| Windows | Core | ConPTY、控制台模式、原生进程与句柄管理 |
| Client | Contracts | 后台发现、启动、HTTP/WebSocket、认证、输出跟随 |
| Host | Core、Contracts、Windows | 本地服务、会话编排、存储、配额、恢复与通知调度 |
| Cli | Client、Windows | 参数解析、终端输入输出、尺寸变化和退出码 |
| Desktop | Client、Core | WinUI 日志与管理界面、托盘、通知发送与激活 |

Desktop 不引用 Host，不持有 ConPTY，不启用终端输入能力，也不向运行任务发送输入或尺寸变更。输出通过公开 API 取得。通知辅助进程读取 API 后写入专用诊断文件，由 Host 更新通知结果；它不直接修改任务元数据。

## 生命周期与归属

| 状态 | 含义 |
|---|---|
| `Starting` | 记录已创建，正在启动 shell |
| `Running` | shell 已成功启动 |
| `Stopping` | 已请求终止，等待进程结束与输出排空 |
| `Exited` | 已启动的 shell 结束，退出码可为非零 |
| `Failed` | 启动或执行基础设施失败，详情见 `error` |
| `Interrupted` | 恢复记录时发现上次后台未正常完成任务 |

Windows 适配先创建 ConPTY，再以暂停状态创建 shell 并加入本任务的 Job Object，最后恢复执行。Job Object 绑定进程归属并启用关闭时结束所属进程。不会按进程名批量终止。

进程等待与输出读取各自运行。shell 退出后关闭 ConPTY、等待输出排空，再提交完成状态与退出码并调度通知。`IsFinished` 为真时，输出游标可以继续读到最后；只有输出分页返回 `complete` 后客户端才应结束读取。

普通交互 CLI 使用 `Terminate` 断开策略。单次命令以及显式 `--keep` 使用 `Continue`。关闭或退出管理窗口不改变后台任务；后台正常关闭与异常退出都会结束它拥有的活进程。

## 转发与只读显示

CLI 开启原控制台的 VT 输入输出并取消本地行缓冲与回显，把输入字节转发给 shell，由 shell 完成编辑与回显。退出时恢复原控制台模式。终端尺寸变化经输入 WebSocket 的 `resize` 消息传递。

ConPTY 输出是终端呈现流，stdout 与 stderr 已合并。Host 保存字节，Client 使用 Base64 HTTP 分页读取；传输层不对任意块直接转换为字符串。CLI 直接写回原终端，窗口用 `TextLog` 增量解码 UTF-8 并去除常见 CSI、OSC 等序列。

窗口显示逻辑日志行，每个逻辑行拥有一个行号。宽度变化导致的视觉换行保留同一个行号，不调整真正的 ConPTY 尺寸。纯文本视图处理回车、换行、退格，以及 ConPTY 定位到行首时的输出分隔，但不实现任意光标编辑、终端屏幕缓冲或全屏程序回放。显示保留近期约 256,000 字符、最多 10,000 行，按完整旧行裁剪并保留绝对行号；当前超长单行会超过字符保留阈值，以保持同一逻辑行完整。复制日志针对当前保留的文本视图，完整原始记录可另行导出。

任务的最新可读输出预览由后台维护，供任务卡片和自动化客户端使用。预览是派生文本，不代替原始输出；超过落盘上限时仍可继续更新，完成后随元数据保存。运行中定期检查点并非逐字节持久化，后台异常退出可能丢失最后一小段预览。

## 持久化、配额与恢复

默认根目录为 `%LOCALAPPDATA%\ShellTrack`。CLI/窗口的 `--data-dir` 和 `SHELLTRACK_DATA_DIR` 可以选择其他目录；直接启动 Host 时使用 `--data-dir`。Host 会为根目录设置当前 Windows 用户的文件访问控制，并持有排他锁。

```text
host.lock                           当前数据根目录的后台排他锁
connection.json                     动态端口、Host ID、进程 ID
credentials.json                    read / manage / terminal 凭据
desktop-settings.json               查看器的详情与跟随输出偏好
sessions/<taskId>/
  request.json                      原始创建参数，用于 requestId 幂等比较
  metadata.json                     当前参数、状态、时间、退出码、通知和输出长度
  output.bin                        原始 ConPTY 输出
  sizes.jsonl                       调整尺寸时的输出位置、时间、列数与行数
notifications/<taskId>.json          通知辅助进程的 Windows 诊断结果
```

元数据先写临时文件再替换，输出边排空边写入并刷新。没有数据库事务或崩溃恢复日志，不承诺断电瞬间的最后一段数据一定落盘。

默认每任务记录上限是 64 MiB，总输出配额是 1 GiB。创建新任务时，已完成任务计入已保存字节，运行任务按完整单任务上限预留额度。最多 16 个任务并发运行。空间不足时创建返回冲突，需要清理已结束历史；不会为腾空间随意删除未过期记录。

到达单任务上限或落盘失败时，Host 继续排空终端，在 `outputTruncated` 和错误字段中记录不完整。额外输出放入每任务 4 MiB 有界内存环。`outputLength` 为终端累计产生的虚拟字节位置，`recordedLength` 为文件实际保存长度，两者可能不同。

输出读取先读取已保存前缀，再读取仍在内存环中的部分。缓冲淘汰后或后台重启后，无法补齐的区间通过 `gap` 明确报告，游标跳到下一段可用输出。慢查看器不能拖慢终端排空，也不会导致无限内存增长。窗口导出仅保存已落盘快照；CLI 跟随导出能获得当时仍可读取的实时段，但应处理缺口警告。

默认保留已结束历史 7 天。清理发生在后台启动、创建任务与每小时检查时，不按时间删除运行任务。删除历史会一并删除输出和通知诊断。

启动恢复会读取元数据与输出文件，并用文件实际长度修正保存字节数。未结束状态改为 `Interrupted`。内存环不会恢复，旧事件不会重放，shell 不会重新启动；客户端必须获取新的快照。

## 本地 API 与安全边界

Host 只监听 `127.0.0.1` 动态端口。每次启动生成新的 Host ID 与三份令牌；客户端先读取本地发现和凭据文件，再验证 `/v1/health`。所有查询和 WebSocket 握手都要求有效凭据，管理操作要求 `manage`，终端输入连接要求独立 `terminal` 凭据。

当前实现拒绝带 `Origin` 的请求，并检查 HTTP Host 为 `127.0.0.1`，没有浏览器 CORS 或远程访问模式。令牌放在 Authorization 头，不放在 URL。窗口客户端默认只保留查询/管理凭据。

这些机制保护跨用户文件访问与误用，不抵御同一用户权限下的恶意程序。同用户程序可读取凭据文件；终端输出也可能包含密码或其他敏感数据。原始输入默认不记录，创建时的命令参数仍会保存在元数据中。

## 桌面与通知

WinUI 3 采用 unpackaged、Windows App SDK 自包含部署。DPI manifest 使用 PerMonitorV2；XAML 使用设备无关尺寸，初始窗口大小按当前 DPI 换算为物理像素。150% 缩放下整体字体清晰度已由用户确认修复。

窗口关闭后隐藏到托盘。双击托盘图标重新打开，托盘菜单与窗口“退出”只关闭查看器。每个数据根目录的普通查看窗口使用单实例激活；通知辅助进程单独运行。详情和跟随输出偏好保存在独立 `desktop-settings.json`，不改变任务元数据。

Host 在完成时查看任务当前通知开关，启动桌面辅助入口读取任务并提交 Windows 通知。通知结果记录 `pending`、`submitted`、`blocked`、`unavailable`、`failed` 或 `interrupted`，以及 Windows ID、应用设置、系统通知状态和历史查询结果。未发送完成的通知在后台恢复时不会自动重发。

`submitted` 不等于用户看到弹窗。当前环境出现过 API 接受且历史查询存在、用户仍看不到通知的情况；实际显示与点击激活尚未完成用户验收。通知失败不会改变任务的执行结果。
